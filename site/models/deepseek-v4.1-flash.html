Run DeepSeek V4.1 Flash locally on one 32 GB GPU

DeepSeek V4.1 Flash is a mixture-of-experts model with 763 billion parameters. As a 2-bit GGUF it is 232 GiB, seven times the memory of a 32 GB card. FLE Link runs it anyway: the FLE engine keeps the experts in RAM, puts the busiest ones on the GPU and lets a small draft model (DSpark) propose tokens that the big model checks.

flelink run deepseek-v41-ista-dspark
flelink run rin-deepseek-v41-dspark

What you need

One NVIDIA card with 32 GB, 128 GB of RAM and about 260 GB on a fast NVMe. Of the 128 GB the model takes 120 GB, pinned so it cannot be swapped out; 8 GB stay with the system. FLE Link installs the FLE engine (v1.2.5 or newer) by itself.

Structured output and tool calls

A 2-bit quant that agrees with the original on 83.5 % of next tokens: do strict formats break? Measured on 11 Nov 2026 with the same quant (ISTA IQ2_XXS), thinking on, and for the JSON rows without a grammar or JSON mode:

TaskResultDetails
JSON to a given schema26/26 validnested objects, enums, escaped strings; no markdown fences, no extra text
Long strict output20 and 40 rows validno repeated rows; the 60-row case hit the 4000-token cap at row 51, clean up to there
Single tool calls, 8 tools16/16right tool and valid arguments
Short agent loops5/5 solved2 to 3 tool steps with simulated tools; 11 calls, none invalid, none repeated

A small sample: short loops, English only, and it was not checked whether the server constrains the tool-call syntax itself. Agent runs over hours are not covered; that is where a 2-bit quant would be expected to show it first.

Good to know

  • The recipe deepseek-v41-ista-dspark uses ISTA DASLab's GSQ-RCO quant (IQ2_XXS) with the DSpark draft model. The draft does not change the answer: the model checks every drafted token.
  • Rin (rin-deepseek-v41-dspark) is the same model split into a hot half that stays on the GPU and a cold half served from RAM. It is a little faster and a little worse than the quant it is made from; the model card has the numbers.
  • The 2-bit quant itself is lossy: its next token agrees with the original weights 83.5 to 85.2 % of the time.
